# AGENTS.md

Project guidance for AI coding agents working in this repository.

## Public Repo

This is the public `coralogix/coralogix-operator` repo. Keep internal ticket IDs, customer names, private URLs, kubeconfigs, API keys, and other secrets out of committed code, comments, docs, samples, and tests.

Use generic, public-safe names in examples and fixtures.

## Architecture

This is a Kubebuilder v4 operator for `coralogix.com` custom resources.

API types live under `api/coralogix/v1alpha1` and `api/coralogix/v1beta1`. Generated DeepCopy code lives in `zz_generated.deepcopy.go`.

`cmd/main.go` wires scheme registration, config, Coralogix SDK clients, controller registration, optional PrometheusRule integration, health checks, and metrics.

Most resource controllers live in `internal/controller/coralogix/v1alpha1`. `Alert` lives in `internal/controller/coralogix/v1beta1`.

Most resource controllers delegate lifecycle flow to `internal/controller/coralogix/coralogix-reconciler/`. The shared reconciler handles create/update/delete routing, finalizers, `RemoteSynced` conditions, metrics, selector mismatch cleanup, and missing remote resources.

`internal/config/` owns flags, environment variables, region/domain URL derivation, selectors, reconcile intervals, and controller-runtime client/scheme globals.

`internal/utils/` holds kind constants, labels/annotations, condition reasons, and small shared helpers. `internal/monitoring/` owns operator/resource metrics.

`Group` has no User CRD. Member emails are resolved with the Users Search OpenAPI, which takes the team from the API key, then written on Team Groups OpenAPI. `spec.customRoles` is a read fallback for Groups created against Helm chart 1.0; prefer `spec.customRole`.

## API and Codegen

Treat Go API types and Kubebuilder markers as the public CRD contract. Preserve backward compatibility unless a breaking change is explicitly requested.

For Coralogix API semantics, use the pinned `coralogix-management-sdk` and, when SDK behavior is ambiguous, the protobuf definitions from the canonical `coralogix/cx-management-apis` repository. This repo does not commit protobuf definitions.

Pay attention to presence semantics: pointers, protobuf `optional`, wrappers, empty slices, and zero values are not interchangeable.

For released enums, keep the CRD value set and conversion aligned. An omitted optional enum can be valid even when an explicit API zero value is not.

Do not hand-edit generated files: `zz_generated.deepcopy.go`, `config/crd/bases/*.yaml`, or `docs/api.md`. Change source types/markers and run the relevant generation target.

When a handwritten kind becomes generated, remove its old CRD entry from `config/crd/kustomization.yaml`. Keep one entry in the generated block. Build `config/default` with Kustomize to check for duplicate resources.

In opgen, an empty API object is a present value when its pointer is set. Preserve `{}` in Create and Update requests. A released CRD can use a pointer map with `MaxProperties=0`; state that shape with `emptyObject: map`.

An API set can appear as a plain CR list. Use `collection: list` for that released shape. If Kubernetes identifies items by a field, add `listMapKey` for a required string item field. Preserve item order and values in the API request.

When changing a CRD field, update the full path:

- API type, JSON tag, validation/defaulting markers, and status fields.
- Controller model conversion and create/update/delete behavior.
- Samples under `config/samples/`.
- Relevant KUTTL/e2e fixtures.
- Generated DeepCopy, CRDs/RBAC, API docs, and Helm chart CRDs.

When adding a new top-level status field to a kind, decide whether `clearRemoteStatus` in the shared reconciler should remove it during selector-mismatch cleanup, or whether it must survive the reset (like Dashboard's `status.imported`).

## Operator Generator (opgen)

`tools/opgen` generates a kind from the API contract: the `openapi.yaml` of the pinned management SDK. It is its own Go module and uses the shared `iac` module of the SDK repository.

`tools/opgen/kinds.yaml` lists every generated kind. `make codegen` runs `opgen generate` for every listed kind, then `make generate manifests generate-api-docs helm-update-crds`. CI fails when a generated file is stale.

```bash
make codegen                                     # generate every listed kind
make opgen-test                                  # build, vet, and test the generator
cd tools/opgen && go run ./cmd/opgen check \
  --resource Thing --openapi /path/to/candidate/openapi.yaml   # check a candidate contract
```

- One issue stops the run, and nothing is written. `check` reports every issue with its code.
- The generator writes only files whose first line is its header (`Code generated by coralogix-operator-codegen. DO NOT EDIT.`, or the older form with a version in it). It never replaces a handwritten file. It removes a generated file of a kind that is no longer listed.
- When the generator adds an output directory, include it in stale-file cleanup. Test that removing the kind or its output configuration removes the generated file and keeps handwritten files.
- Per kind it writes `<kind>_types.go`, `<kind>_convert.go`, `<kind>_controller.go`, the sample `config/samples/v1alpha1/generated/<kind>.yaml`, and the e2e test `tests/e2e/<kind>_generated_test.go`. It also writes `generated_registry.go`, `internal/utils/generated_kinds.go`, and the `# BEGIN generated kinds` blocks of `PROJECT`, `config/crd/kustomization.yaml`, and the Helm `cluster_role.yaml`.
- Do not hand-edit generated files. Change the contract or the generator, and run `make codegen`.
- A contract `number` with format `float` or `double` renders as `resource.Quantity` and converts with `AsApproximateFloat64`. A Quantity is int-or-string in the CRD, so the generator never writes `Minimum` or `Maximum` on it. Check numeric bounds in the API, or with a CEL `quantity()` rule. A number default is written as a quoted decimal string, because Kubernetes rejects a number literal as the default of an int-or-string field. A map of numbers is not supported yet.
- An API field that Create does not have but Update does (`OPERATOR_UPDATE_ONLY_FIELD`) stops the run. The renderer cannot send a field in only one request, and it must not drop one without a word. Add `skip: true` for the field to keep it out of the CR and the requests, or extend the renderer.
- A handwritten entry of a generated kind in `PROJECT`, `config/crd/kustomization.yaml`, or the Helm `cluster_role.yaml` stops the run (`OPERATOR_DUPLICATE_ENTRY`). Remove the handwritten entry when a kind moves to generated code.
- `tools/opgen/kinds/<kind>/e2e.yaml` holds only the e2e values that the contract cannot state.
- Choose generated sample values that pass admission on the oldest Kubernetes version in CI. A selected oneOf arm with an empty object can fail CEL validation on older versions.
- Use values from a working API fixture for strings that name server-side resources, such as output schemas. The API contract can validate their syntax but cannot prove they exist.
- The live API can require a field that the contract marks optional, or a nonempty list that the contract permits empty. Add these values under `minimal` in the kind's `e2e.yaml`. Verify the minimal resource against the live API.
- For a released kind, `e2e.yaml` may also fix the spec accepted by an old chart. Opgen generates its upgrade check. Keep that old spec fixed when the current API gains fields. The current generated e2e test gets the new fields.
- The generated e2e update changes a mutable scalar outside a oneOf. It tries top-level fields first, then fields inside root `groups`. An `e2e.yaml` `update.field` inside a root group uses a dotted CR JSON path, such as `routing.timeout`.
- A field with a line in `behavior-overrides.yaml` keeps its released behavior. A field without a line follows the contract. `TestReleasedKindTakesANewFieldWithoutOverrides` adds a field to the pinned contract of a released kind and checks that it reaches the type, the conversions, the sample, and the e2e test with no new line. A key lands with the first kind that needs it, together with a golden fixture.
- When one API component appears at several CR paths, keep validation for each path separate. A field override at one path must not change admission at another path.
- `tools/opgen/kinds/<kind>/behavior-overrides.yaml` has `resource`, `mode` (`existing` for a kind that users already have, `new` otherwise), and these keys:
  - `validators.inferred`: `true` keeps contract limits and defaults. Use it for released kinds so new API fields get their rules without new override lines. `validators.fields.<spec path>.inferred: false` keeps an old field without those rules. Paths use CR property names after `name` and `groups` overrides, including nested fields. `remove` and `add` replace exact Kubebuilder validation or default markers. Use `#type` after an object path to change markers on its Go type, such as `spec.target#type`; the path without the suffix changes markers on the field. A required field stays required. Mode `existing` requires `validators.inferred`; mode `new` follows the contract by default.
  - `api.updateIDInBody`: Update has no id in its path, so the generated Update copies the status id into the body. With `requestWrapper`, opgen reads the contract to find whether the id is inside or beside the wrapper.
  - The shared `iac` API keys `operations`, `customMethods`, `serverSetID`, `idProperty`, `clientSetID`, `delete.operation`, `updateMaskInBody`, and `requestWrapper` are supported. A wrapped Create response must contain the resource.
  - `api.requestValues` sets string fields beside `requestWrapper`. Each Create or Update field takes `source: spec.<field>`, `source: uuid` with a prefix in `value`, or `source: literal` with its value. The renderer rejects an unmapped sibling field.
  - An `api` key may state its default (`false`) in either mode. Mode `new` follows the contract, so it sets no key to another value. An `api` section without a key stops the run.
  - `ref` on a field line turns a string or integer API id into a CR reference. It also handles lists. `kind` names the target CR; `version` selects its API version. `form: resourceRefOnly` keeps a CR-only reference. `form: split` adds the CR field named by `resourceField` beside the backend id field. `backendIdType` keeps a released numeric backend id type. `form: named` accepts a backend name and calls the exported function in `lookup` through a second SDK client. `form: namedBackendOnly` has no CR arm; a released kind can keep its handwritten type with `type` and `idField`. Name lookups use a request-local cache. For a released kind, `name` keeps the CR property name. `ref.type: NCRef` keeps the released one-rule validation for a plain string reference.
  - The API server enforces `format: int32` on an integer field, and loosening admission is a breaking change. When a released `int32` field becomes a wider generated type, keep the released format with `add: ['+kubebuilder:validation:Format=int32']`.
  - Numeric API resource IDs remain strings in `status.id`. Generated Update, Delete, and e2e code parses them with the API bit width. Generated Create code formats the returned number. A contract `date-time` field uses `metav1.Time` and sends its `time.Time` value to the SDK.
  - `opgen check-schema --base <commit>` compares rules on released CRD fields with the base commit. New optional fields need no approval. A changed old rule needs its exact before and after hashes and a reason in `tools/opgen/approved-schema-changes.yaml`.
  - `readOnly: true` on a field line states that the server owns it when the contract does not. This lets `serverSetID` and `updateIDInBody` use the status id together. A new kind cannot set it.
  - `skip: true` omits a released top-level API field from the CR and requests. It cannot share a line with another field key. The shared model rejects a skipped field that a request requires.
  - `unwrap` names one-property API components that the released CR shows as their inner value. A field line can set `unwrap: true` for one place or `unwrap: false` to keep a listed wrapper there. Create and Update restore the API wrapper.
  - `groups` at the root or under `types.<Component>` places API fields under a required CR object. A oneOf group moves with all its arms; ordinary fields may share that object. It needs a full-replace Update; PATCH grouping needs nested mask support.
  - `requestValueBy` on a field line hides a string or enum API field from the CR. Create and Update set its value from the selected optional object arm. The map names each arm and its API value. An enum zero value cannot represent a selected arm.
  - `requireOne: true` keeps an exactly-one CEL rule when the API oneOf permits zero arms. Set it on one arm, on a field that holds a oneOf, or on a `groups` entry that holds every arm.
  - `required: true` keeps a released CR field required and states its released presence behavior, even when the API also requires it. `optional: true` keeps a field optional when a request requires it. `name` keeps the released CR property name. Conversions still use the API property. These keys apply only to an existing kind.
  - `finalizer` keeps the released finalizer name of an existing kind. The generated name is `kebab(Kind).coralogix.com/finalizer`. A released kind with another name must set it, or deleting its existing objects hangs. It is an operator key, so the shared `iac` module does not know it.
  - `enums.<component>` lists accepted API `values` and `rejected` values. `zero`, `names`, `verbatim`, and `trimPrefix` set CR spellings. `aliases` maps one accepted CR spelling to another business value for requests. Each accepted spelling maps to a checked SDK constant. A new kind uses the contract without an enum line.
  - Check values before writing them into Kubebuilder markers. Reject syntax characters that controller-gen can read as marker separators, or encode the values so the generated CRD keeps them exactly.
- Goldens: `cd tools/opgen && go test ./internal/generator -update` rewrites them. Review the golden diff like code.
- When a synthetic CR field changes, update envtest objects that use its golden CRD and run `make unit-tests`.
- Version: the generated files have no version in their header. `tools/opgen/versions.yaml` is generated and holds `version.Current` of `tools/opgen/internal/version/version.go` for each kind, so a new version changes one file. Give the generator a new version (during beta, the next `-beta.N`) when a change changes what it produces: a generated file, a golden file, or a `check` report. A refactor with the same output keeps the version. CI enforces this with `tools/opgen/scripts/check-version-change.sh`: it builds opgen at the base commit and at the PR, runs both on the same input, and compares the output.

## Reconciliation

Create, update, delete, and selector-mismatch cleanup must be idempotent.

Deletion must tolerate remote resources that are already gone.

Failed create/update paths must not leave misleading status IDs or `RemoteSynced=True`.

Use the shared reconciler for condition/status transitions unless a controller has a concrete reason to own them.

Return contextual errors from controllers; do not log and return the same error.

Before changing finalizer or status order, consider partial failures, retries, conflicts, and remote resources created before Kubernetes status/finalizer updates succeed.

Preserve `observedGeneration` behavior and `RemoteSynced` reasons from `internal/utils/conditions.go`.

When a remote resource is missing during update, the shared reconciler removes `status.id` so the next reconciliation can recreate it.

An optional reference that is not set must leave its field out of the request. Do not send the zero id: the API reads it as a real id and rejects it.

During a Helm upgrade, the old operator pod can stay leader for about 20–30 seconds after the new CRDs are applied. It writes objects back with its own Go types, so it drops spec fields it does not know. The new operator must handle the result: a resource with a status id and without those fields.

Deep-copy status values that contain slices or maps before change detection. A shallow copy can hide in-place condition changes.

## Review Checklist

- Check CRD compatibility: field names, JSON tags, enum strings, defaulting, validation markers, required/optional behavior, and status shape.
- Check `+kubebuilder:default` against presence semantics: a zero-value default on a non-pointer `omitempty` field is a no-op, and a non-zero default needs a pointer field.
- Check that the Go type can decode every value that admission accepts. One stored object that fails to decode, such as a negative number in a `uint32` field, fails the typed List of the whole kind, so the controller stops reconciling every object of that kind.
- Keep CRD validation no stricter than the remote API. A validation marker or CEL rule may move a remote error earlier, from a failed reconcile to admission. It must not reject a value the API accepts. Loosening a rule later is safe; tightening one is a breaking change, so an unverified rule has to be settled before it ships.
- Bound lists used by CEL rules with the API limit. An unbounded list can make a nested CRD exceed the Kubernetes CEL cost budget.
- Trace touched fields end to end: CR spec -> controller conversion -> Coralogix API request -> remote response -> status/conditions -> samples/docs.
- Check null, empty, pointer, wrapper, and zero-value drift between Kubernetes objects, Go structs, SDK models, protobufs, and remote API defaults.
- Check finalizer/status ordering for partial failures, retries, conflicts, remote not-found responses, and selector mismatch cleanup.
- Confirm generated artifacts are in sync after API changes: DeepCopy, CRDs, docs, Helm chart CRDs, and samples.
- Prefer regression tests for create, second reconcile, update, remove optional fields, delete when remote is already gone, and status-missing recovery.

## Runtime Configuration

- `CORALOGIX_API_KEY` is required.
- Exactly one of `CORALOGIX_REGION` (`AP1`, `AP2`, `AP3`, `EU1`, `EU2`, `US1`, `US2`, `US3`) or `CORALOGIX_DOMAIN` is required.
- Optional selectors: `LABEL_SELECTOR` and `NAMESPACE_SELECTOR`.
- Per-kind reconcile intervals use `<KIND>_RECONCILE_INTERVAL_SECONDS`; nonzero values must be at least 30 seconds.

```bash

make manifests          # Regenerate CRDs and RBAC
make generate           # Regenerate DeepCopy methods

```

```bash
make integration-tests  # kubectl kuttl test

```

`make unit-tests` uses envtest assets for Kubernetes `1.30.3` and writes `cover.out`; it no longer needs a running cluster. Integration and e2e tests require a Kubernetes cluster and real Coralogix access.

## Validation

Use focused unit/envtest coverage for controller behavior, validation, status transitions, selector behavior, and idempotent delete/update flows.

Use KUTTL or e2e coverage when Kubernetes wiring, CRDs, Helm packaging, or real API behavior is part of the risk.

The live suites (e2e, Helm e2e, integration, upgrade) run from `.github/workflows/live-tests.yaml`, one after another, because they share one Coralogix team. Each suite is a reusable workflow in its own file. The `Live tests result` job is the check that branch protection requires. Keep its name stable: renaming it blocks every PR until the ruleset changes. To add a suite, add a `uses:` job to `live-tests.yaml`, chain it with `needs`, and add it to the `needs` of `live-tests-result` and `notify-failure`. A suite that is not in `live-tests-result` does not block merges.

When a test reads a remote resource, do not depend on the order of items inside a returned list. The API can return
list elements in any order. Assert on a set or find the element by an identifying field, instead of indexing a fixed
position.

Before finishing code changes, prefer:

```bash
make generate
make manifests
make lint
make unit-tests
```

For CRD or chart changes, also run:

```bash
make generate-api-docs
make helm-sync-check
```

If tests cannot be run, state the skipped command and why it was skipped.

## Repo Map

Use this map to choose the smallest useful reading set before opening broad directories.

- `cmd/main.go` wires manager setup, SDK clients, schemes, controllers, health checks, and metrics.
- `api/coralogix/v1alpha1/*_types.go` and `api/coralogix/v1beta1/*_types.go` define CRD specs/statuses and Kubebuilder markers.
- `internal/controller/coralogix/coralogix-reconciler/coralogix_reconciler.go` is the shared lifecycle engine.
- `internal/controller/coralogix/v1alpha1/*_controller.go` and `internal/controller/coralogix/v1beta1/*_controller.go` contain per-kind logic and model conversion.
- `internal/controller/prometheusrule_controller.go` handles Prometheus Operator integration.
- `internal/config/` owns runtime config, selectors, reconcile intervals, and controller-runtime globals.
- `internal/utils/` holds kind names, labels/annotations, condition reasons, and shared helpers.
- `config/crd/bases/`, `config/rbac/`, `config/manager/`, `config/default/`, and `config/prometheus/` are generated or assembled deployment manifests.
- `config/samples/` contains public sample CRs.
- `charts/coralogix-operator/` contains the Helm chart.
- `docs/api.md` is generated from CRDs. `docs/prometheus-integration.md` and `docs/metrics.md` are hand-written.
- `tests/e2e/` contains Go/Ginkgo tests that hit real Coralogix APIs. `tests/integration/` contains KUTTL scenarios.
- `tools/cxo-observer/` is a supporting observer tool.
- `.claude/skills/<skill-name>/SKILL.md` stores short agent lessons. `.cursor/skills` is a symlink to that directory.

Primary resource kinds:

- `v1beta1`: `Alert`.
- `v1alpha1`: `AIEvaluation`, `AlertScheduler`, `ApiKey`, `ArchiveLogsTarget`, `ArchiveMetricsTarget`, `Connector`, `CustomEnrichment`, `CustomRole`, `Dashboard`, `DashboardsFolder`, `Enrichment`, `Events2Metric`, `GlobalRouter`, `Group`, `Integration`, `IPAccess`, `OutboundWebhook`, `Preset`, `QuotaAllocationRuleSet`, `RecordingRuleGroupSet`, `RuleGroup`, `Scope`, `SLO`, `TCOLogsPolicies`, `TCORumPolicies`, `TCOTracesPolicies`, `View`, `ViewFolder`.
